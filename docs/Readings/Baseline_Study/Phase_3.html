3.1

训练循环 — 模型怎么"变聪明"

一个 step 的 8 个动作 · 双优化器分工 · 梯度裁剪
backward() vs step() — "想清楚" vs "动手改"核心概念
backward() 通过自动微分计算 ∂loss/∂w 存入 .grad；optimizer.step() 按梯度更新 w.data。两者解耦。
想象烤面包机有上百万个旋钮。backward() = 数学家拿着计算器算出"每个旋钮该往哪边转、转多少"，把结果写在便签纸上（不碰旋钮）。optimizer.step() = 工人按便签纸真正去拧旋钮。zero_grad() = 下一轮前撕掉旧便签，否则新旧梯度会累加导致参数乱跑。
双优化器 — 兼职员工 + 全职高管推荐系统标配
参数分两类：sparse (nn.Embedding) 占 95% 但每步只用 0.1%；dense (Linear/LN) 占 5% 但每步全用。各用专属优化器。
Embedding 表像有 1000 万兼职员工的人才库，每天只叫 300 人上班——用 Adagrad："谁来得少给谁涨工资"，冷门 ID 一旦出现就大步更新。其他参数像 50 个全职高管，天天都在——用 AdamW：动量 + 自适应 + 权重衰减，Transformer 标配。两类参数用同一种优化器要么浪费显存要么调坏精密层。
梯度裁剪 — 悬崖上的安全绳核心概念
clip_grad_norm_(max_norm=1.0)：所有参数梯度看作一根向量，总长超 1.0 则等比例缩小，方向不变。
训练偶尔出现梯度爆炸——某个 batch 梯度突然变巨大，optimizer.step() 把参数推到荒谬位置，模型瞬间崩坏。梯度裁剪就是给每步设上限：平时每步 1 米没问题，突然要飞 100 米 → 安全绳拽回 1 米。方向不变，步子变短。
Adagrad 周期性重置 — 给老员工新机会工程细节
每个 epoch 后重建 Adagrad，重置累积平方梯度 s，避免学习率衰减到接近 0 而"学不动"。
Adagrad 的累积量 s 只增不减——训练久了学习率衰减到接近 0，高基数 Embedding 陷入"学不动"。重建相当于给它们一次重新出发的机会。这是来自快手 MultiEpoch 论文的技巧。
一个 training step 的完整 8 步
取 batch → zero_grad → forward → loss → backward → clip_grad → step ×2 → 日志
和你的训练曲线的对应

Loss 频繁 spike → sparse_lr=0.05 给 Embedding 的更新步子太大，即使有梯度裁剪也没完全压住震荡。这正是你看到的 0.3 主体 + 频繁跳到 0.5-0.75 的现象。

改进方向：降 sparse_lr 到 0.01-0.02 是低成本改进的首选。

3.2

验证与早停 — 知道何时该停

train vs eval 的本质区别 · AUC 排序能力 · EarlyStopping 机制

训练 (train)

  • 用训练集（前 90% Row Groups）
  • model.train() — Dropout 开启
  • 算梯度 (backward)
  • 更新参数 (step)
  • 看 loss，决定怎么改

验证 (evaluate)

  • 用验证集（后 10%，模型没见过）
  • model.eval() — Dropout 关闭
  • torch.no_grad() 不算梯度
  • 不更新任何参数
  • 看 AUC，判模型好坏
为什么必须分开？— 防止"应试作弊"核心概念
仅用训练集衡量会激励模型死记硬背 → 过拟合。验证集是"没见过的考卷"，AUC 才有意义。
就像学生用 100 道练习题学习，光看练习题分数无法判断他真懂还是死记。再出 10 道新题考——新题考好才算真懂。验证集就是这 10 道新题。训练 loss 几乎总在下降，但验证 AUC 会先升后降——后期开始死记训练集时，验证 AUC 反而跌。
AUC — 排序能力的精确定义核心概念
AUC = P(score(positive) > score(negative))，对类别不平衡稳健，不依赖阈值。
AUC = 随机抽一个正样本和一个负样本，模型给正样本打更高分的概率。 0.5 = 瞎猜，1.0 = 完美。推荐系统偏爱 AUC 因为：① 不依赖阈值；② 对不平衡稳健（95% 都猜"不点"也只得 0.5 AUC）；③ 直接对应推荐的核心任务——排序能力。
EarlyStopping patience=5 — 连输 5 把离场核心概念
连续 5 次验证 AUC 未创新高则停训。每次创新高 counter 立刻归零，给模型充分翻身机会。
就像赌场规矩：你赢了一些钱（AUC 在涨），怕赌久会输回去。连续 5 把没新高就离场，保住目前赢的最多的那一刻的筹码。关键设计：每次创新高 counter 立刻重置——给模型留足翻身空间，避免被局部波动误判。
Checkpoint — 创新高才存档代码机制
torch.save(state_dict)，仅 AUC 创新高时触发。配套 schema.json + ns_groups.json + train_config.json 三个 sidecar 文件。
主文件 model.pt 只存参数数值（state_dict），不存模型架构。加载时必须先用同样的超参重建架构再灌入参数。配套三个 sidecar 文件让推理脚本能独立运行，不用回去找训练配置。旧 checkpoint 会自动删除，避免磁盘越积越多。
和你的训练结果的对应

你的 checkpoint: global_step28992.layer=2.head=4.hidden=64.best_model — 在第 28992 步达到验证集 AUC 最高，系统自动保存。

训练终止机制: 之后 AUC 再也没涨过，连续 5 次验证未改进，EarlyStopping 在 ~step 47000 终止训练。它保护了你的模型不至于过拟合越走越远。

3.3

损失函数 — 怎么"扣分"

BCE vs Focal Loss · α 和 γ 两个旋钮
BCE Loss — 统一扣分制默认 loss
Binary Cross-Entropy：-[y·log(p) + (1-y)·log(1-p)]，所有样本同等权重。
每道题对错都按统一标准扣分——答错扣 5 分，答对加 0 分。不管样本是正是负、好不好判，规则一样。优点：简单、稳定、和 AUC 高度相关。缺点：当类别极度不平衡时（95% 负样本），简单样本的 loss 会淹没难样本，模型陷入"全猜负"的懒惰解。
Focal Loss — 重点批改难题预留选项
在 BCE 前乘上 (1-p_t)^γ 压扁简单样本，让模型聚焦于难样本。α 控制类别权重。
老师改卷时多加两条规则：答得很笃定（不管对错）→ 几乎不看；答得犹豫或错得离谱 → 重点改。模型预测概率 0.9 的简单样本（γ=2 时）loss 被压到 1/100；预测 0.5 的迷糊样本 loss 几乎不变。梯度信号被强制引导到难样本上。
γ (gamma) — 聚焦强度超参数
γ=0 退化成 BCE，γ=2 论文标准值，γ>5 可能过度聚焦导致训练不稳。
控制"对简单样本的压扁程度"。γ 越大越聚焦难样本。γ=2 是 Focal Loss 论文的稳妥默认——简单样本 loss 被压成 1/100，难样本 loss 几乎不变。
α (alpha) — 类别权重超参数
本实现中 alpha = 正样本权重。α < 0.5 压低正样本，α > 0.5 抬高正样本。默认 0.1。
直接给正负样本不同权重。γ 管"难易"，α 管"多少"，两个旋钮独立调。代码默认 0.1 是"压低正样本"——具体方向要根据数据集正负比例试。PCVR 场景常用 0.25 或 0.75。
关键判断

Focal Loss 不是万能的。它需要调参，调不好可能比 BCE 还差。工业实践里 Focal 是调参选项而非默认——先用 BCE 跑通，发现模型"摆烂"才考虑切换。Baseline 默认 BCE 是正确选择。

改进方向

你的 baseline 用 BCE。如果将来尝试 Focal Loss，命令行加：bash run.sh --loss_type focal --focal_alpha 0.25 --focal_gamma 2.0

建议作为后期实验——先把训练策略和特征工程做好，再考虑换 loss。
