2.1

NS Tokenizer — 制作名片

把零散的非序列特征打包成标准 token
两种打包方式核心概念
GroupNSTokenizer 按语义分组投影；RankMixerNSTokenizer 全拼后等长切段投影。Baseline 用 RankMixer。
Group 模式 = 按类别装箱（衣服一箱、书籍一箱），箱数被类别数锁死。RankMixer 模式 = 按数量平均装箱（你说要 5 个箱子就切 5 段），灵活但语义可能被打散。实践中 RankMixer 效果不差，因为模型有能力自己重新组织语义。
5 + 1 + 2 = 8 个 NS token代码参数
user_ns_tokens=5, user_dense→1 token via Linear projection, item_ns_tokens=2. 总 num_ns=8。
用户特征丰富（46 列）→ 给 5 个箱子。用户连续特征 → 单独投影成 1 个 token。广告特征少（14 列）→ 2 个箱子够了。这 8 个 token 就是用户和广告的"浓缩名片"。
这才是真正的降维认知更新
从 ~数百维的散乱 embedding 拼接向量，压缩为 (B, T, 64) 的定长 token 序列
Phase 1 的 dataset.py 是"分类整理不变少"。这一步才是真正的信息浓缩——把几百维的散乱信息压成几个 64 维的标准 token。就像把 5000 字的文章概括成 5 个要点。
2.2

序列编码 — 翻译行为日志

Self-Attention + RoPE + Time Bucket Embedding
Self-Attention — 每个 token 环顾四周核心概念
Q=K=V=x，每个 token 与所有其他 token 计算相关性，按权重加权融合信息。复杂度 O(L²·D)。
256 个人开会，每人都发言一遍（Query），其他人举手响应（Key），匹配度高的人详细分享（Value）。会后每人的笔记都"包含了别人的信息"，但各自重点不同。这让模型能捕捉"一周前看了手机壳，今天又在看"这种远距离关联。
RoPE — 旋转位置编码核心概念
对 Q、K 向量按位置旋转角度，使 attention 点积只与相对位置 (m-n) 有关。
普通位置编码 = 给每人发工牌号（绝对位置），模型要费劲算减法才知道"两人差几号"。RoPE = 让每人按位置朝不同方向站，握手时的夹角直接告诉模型"差几位"。好处：更准确的相对距离感知，且能处理训练时没见过的更长序列。
_embed_seq_domain — 序列翻译四步走代码流程
每特征查 Embedding → 拼接 → Linear 投影到 d_model → 加 time_bucket embedding
每个时间步有多个信息（商品 ID、类目、行为类型），各自查各自的 Embedding 表 → 同一时间步的向量首尾拼接 → 过 Linear 压到 64 维 → 加上时间桶标签。最终从整数 ID 变成了 (B, L, 64) 的标准 token 序列。
RoPE + Time Bucket = 互补搭档关键洞察
RoPE 编码序列内位序（第几位），Time Bucket Embedding 编码真实时间间隔（距今多久）。
RoPE 知道"这两步在序列里相邻"，但不知道"它们在真实时间上隔了 3 个月"。时间桶补上这个信息：模型由此能区分"刚刚点的"和"很久以前点的"，学到时间衰减或周期性偏好。
一个域的序列编码流程
seq [B,S,L] 整数 → S 个 Embedding → 拼接 [B,L,S·emb] → Linear+GELU → + time bucket → [B, L, 64]
2.3

Query 三件套 — HyFormer 核心创新

MultiSeqQueryGenerator → CrossAttention → RankMixerBlock
MultiSeqQueryGenerator — 派出调查员HyFormer 核心
ns_flat + MaskedMeanPool(seq) → global_info → Nq 个独立 FFN → Query tokens (B, Nq, D)
把用户名片（NS tokens 摊平）和行为日志的摘要（序列平均池化）揉在一起形成"任务简报"，然后每个调查员（Query）用自己的视角（独立 FFN）从简报里提炼出一个针对性的问题。每条序列独立生成——短期序列和长期序列需要不同的提问方式。
CrossAttention — 调查员查档案HyFormer 核心
Q=(B,Nq,D) 对 KV=(B,L,D) 做交叉注意力，RoPE 只加 K 端。输出 (B,Nq,D)。
调查员带着问题进档案室：扫一遍 256 条记录（Key），发现第 45 条和第 120 条相关性高 → 重点提取这两条的信息（Value），其他 254 条基本忽略。核心价值：把 256 个 token 的长序列蒸馏成 1 个 token 的精华。RoPE 只加在序列端——调查员的"问题"没有时间位置。
RankMixerBlock — 零成本情报交换HyFormer 核心
reshape-transpose 实现零参数 token 间信息交换，再过 FFN 做非线性变换。三种 mode: full / ffn_only / none。
4 个调查员各自带回报告，但彼此不知道对方发现了什么。RankMixer 让他们交换情报：把每份报告切段 → 不同调查员的同位段拼在一起 → 过 FFN 加工。巧妙之处：信息交换通过 reshape-transpose 实现，没有可学习参数，计算成本几乎为零，效果接近 Self-Attention。
HyFormer 的设计哲学

整个 Query 机制的本质是"信息蒸馏"——用少量 Query token 从漫长的序列中提取精华，而不是让下游网络直接面对上千个 token。这既节省计算量，又迫使模型学会"什么信息最重要"。

Query 三件套数据流
NS (B,8,64) + Seq 摘要 → QueryGen → Q (B,1,64) ×4 → CrossAttn → RankMixer ×2层

完整 forward — 端到端 shape 链路

从 ModelInput 到 0~1 概率的完整旅程
步骤操作shape人话
输入ModelInput 7 个字段user_int (B, ~50) 等五盘食材 + 序列三件套
Step 1NS Tokenizer(B, 8, 64)70 列特征浓缩成 8 张名片
Step 2Seq Embedding ×4(B, 256/512, 64)4 条序列翻译成 token
Step 3QueryGenerator(B, 1, 64) ×44 个调查员带着问题出发
Step 4HyFormer Block ×2shape 不变查档案 + 交换情报 × 2 轮
Step 5a拼接 4 个 Q + 摊平(B, 256)4 份报告合并
Step 5bLinear → (B, 64)(B, 64)压缩成最终表示

一句话总结

120 列原始数据 → 8 个名片 token + 4 条序列 token → 4 个调查员带着问题去查序列 → 蒸馏出精华 → 互相交换情报 → 拼起来 → 一个数字：这个用户点击这条广告的概率。
