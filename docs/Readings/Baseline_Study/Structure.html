2

train.py — 指挥官的四项职责

不自己干活，只"装配零件、发号施令"
职责 1：创建数据管道调用 dataset.py
get_pcvr_data(data_dir, schema_path, batch_size=256, valid_ratio=0.1, ...)
调用 dataset.py 的 get_pcvr_data()，获得三个东西：train_loader（训练数据流）、valid_loader（验证数据流）、pcvr_dataset（含 feature schema、vocab sizes 信息）。
职责 2：构建模型调用 model.py
从 dataset 提取 spec → build_feature_specs() → PCVRHyFormer(**model_args)
从 dataset 对象中提取 user_int 的 vocab_size、dense_dim、seq 的 vocab_sizes 等信息，加上命令行传入的超参（d_model=64, num_heads=4, num_hyformer_blocks=2...），拼成 model_args 字典，传给 PCVRHyFormer(**model_args) 构建模型。
职责 3：创建训练器调用 trainer.py
PCVRHyFormerRankingTrainer(model, train_loader, valid_loader, early_stopping, ...)
把前面创建好的 model、train_loader、valid_loader、early_stopping，加上所有训练超参（lr, sparse_lr, loss_type, patience...），传给 PCVRHyFormerRankingTrainer(...)，训练器内部自己创建双优化器。
职责 4：启动 + 收尾工具调用
set_seed(42) → create_logger() → trainer.train() → writer.close()
固定随机种子（utils.set_seed）→ 启动日志（utils.create_logger）→ 调用 trainer.train()，此后 train.py 的使命基本完成。训练结束后关闭 TensorBoard writer。
train.py 的执行顺序
解析 CLI 参数 → set_seed + create_logger → get_pcvr_data() → 提取 spec + 构建模型 → 创建 EarlyStopping → 创建 Trainer → trainer.train()
3

trainer.py — 教练的训练计划

一个 step 8 个动作 · 双优化器 · 验证 + 早停 · 存档管理
__init__：创建双优化器初始化
Adagrad(sparse_params, lr=0.05) + AdamW(dense_params, lr=1e-4)
模型提供 get_sparse_params() 和 get_dense_params() 两个方法，trainer 据此分成两组：Embedding 参数给 Adagrad（"谁来得少给谁涨工资"），其余参数给 AdamW（动量+自适应+权重衰减）。
_train_step：8 个动作核心循环
batch_to_device → make_model_input → zero_grad → forward → loss → backward → clip_grad → step ×2
每 256 条数据执行这 8 步。关键技术点：① 双优化器各自 zero_grad() 和 step()；② backward 之后 step 之前插入 clip_grad_norm_(max_norm=1.0) 防梯度爆炸；③ loss 可选 BCE（统一扣分）或 Focal（重点批改难题）。
evaluate：考试模式验证
model.eval() + torch.no_grad() → 跑验证集 → 算 AUC + LogLoss
关 Dropout、不算梯度、不改参数。用 sklearn 的 roc_auc_score 算 AUC，用 PyTorch 的 binary_cross_entropy_with_logits 算 LogLoss。过滤 NaN 预测——如果梯度爆炸导致输出 NaN，这些样本不参与指标计算。
_handle_validation_result：存档逻辑Checkpoint
AUC 创新高 → 删旧 best → 写 model.pt + 3 个 sidecar
只有当 AUC 实际上超过当前最佳时才写磁盘。保存 4 个文件：model.pt（参数）、schema.json（特征布局）、ns_groups.json（NS 分组）、train_config.json（完整超参）。旧的最佳 checkpoint 自动删除。
trainer.py 和 utils.py 的关系

trainer.py 从 utils.py 引入两个东西：sigmoid_focal_loss（当 loss_type='focal' 时使用）和 EarlyStopping（每轮验证后调用）。trainer 不依赖 utils 的 set_seed 和 create_logger——那些是 train.py 启动时一次性调用的。

4

utils.py — 工具箱的四件工具

被 train.py 和 trainer.py 分别引用，各取所需
set_seed(42)工具 1
锁死 Python random、NumPy、PyTorch CPU/CUDA 所有随机数生成器，cuDNN 设 deterministic。
保证每次训练跑出来的结果可复现。被 train.py 在启动时调用一次。注意：完全 bitwise 确定性还需要关 cuDNN auto-tuning（会降速），这里只开了 deterministic，保留速度。
create_logger(path)工具 2
创建日志系统：文件（DEBUG 级别，详细）+ 控制台（INFO 级别，简洁），带时间戳前缀。
日志前缀格式："日期 时间 - 已运行时长"。比如你看到 "05/12/26 14:32:10 - 2:15:03" 就知道训练跑了 2 小时 15 分。多行消息自动对齐，不会因为前缀长短不一而错位。
EarlyStopping工具 3
跟踪最佳 AUC，计数连续未见涨次数。创新高 → 保存 + counter 归零；没改进 → counter+1；counter≥patience → 喊停。
三个关键设计：① delta 阈值（必须超过 best_score+delta 才算改进，避免浮点波动误判）；② 内存 + 磁盘双保存（best_model 存内存、model.pt 存磁盘）；③ 每次创新高 counter 立刻归零——给模型留足翻身空间。
sigmoid_focal_loss()工具 4
FL(p_t) = -α_t · (1-p_t)^γ · log(p_t)，γ 压扁简单样本，α 调类别权重。
γ=0 退化为 BCE，γ=2 是论文标准值。α 默认 0.1（压低正样本）。Baseline 用 BCE（默认），Focal 是预留选项——调不好可能比 BCE 还差，工业实践里先用 BCE 跑通再说。
utils.py 被谁引用
train.py → set_seed + create_logger + EarlyStopping
trainer.py → sigmoid_focal_loss + EarlyStopping

完整数据流：从 run.sh 到点击概率

跨 5 个文件的端到端旅程
启动阶段（train.py main）Phase 1 → 2 衔接
parse_args → set_seed → create_logger → get_pcvr_data → build model → create trainer → trainer.train()
这里的关键信息流：dataset 对象里的 schema 信息（vocab_sizes, feature_specs）流向 model 的构造函数，model 据此创建正确大小的 Embedding 表和网络层。

如果 schema 说 user_int 某特征 vocab_size=1725，模型的 Embedding 就是 (1725, 64)；如果 schema 说 seq 某域有 5 个 sideinfo 特征，序列编码器就准备 5 张 Embedding 表。
训练阶段（trainer.train）Phase 2 → 3 循环
for epoch in 1..999: for batch in train_loader: _train_step(batch) → evaluate() → early_stopping()
batch 的旅程：Phase 1 的 dataset 产出 batch dict → trainer 的 _batch_to_device 搬上 GPU → _make_model_input 转成 ModelInput → model.forward() 跑 Phase 2 的 5 步流水线 → 得到 logits → 算 loss → backward 算梯度 → step 拧旋钮。

验证的旅程：valid_loader 产出 batch → model.eval() + no_grad → model.predict() → 得到 logits → sklearn 算 AUC → EarlyStopping 判停/继续。
train.py 为什么存在？架构洞察
如果只有 dataset + model + trainer，三者仍然是孤立零件。train.py 是"胶水"——它知道 schema 信息怎么从 dataset 流向 model，知道怎么把 model + data + tools 拼成 trainer。
这就是软件工程的关注点分离：dataset 不关心模型长什么样，model 不关心数据从哪来，trainer 不关心超参从哪传入。train.py 承担了所有"把零件组装起来"的职责。如果换个项目、换个模型架构，你只需要改 train.py 的组装逻辑，其他四个文件可以保持不变。
完整端到端数据流
run.sh → train.py 装配 → dataset 配菜 → model 大厨 → trainer 教练 → utils 工具箱 → checkpoint 存档
6

三大 Phase 统一视角

把 Phase 1/2/3 的"矛盾框架"映射到五个文件上
Phase 1 — dataset.py格式矛盾
主要矛盾：真实数据的非结构化特征 vs GPU 计算要求的规整矩阵
① 分类 = 语义理解→工程分派（数据驱动）
② 对齐 = 对硬件的妥协（截断补零与业务逻辑无关）
③ 打包 = 效率工程（256 条/batch + 打乱）
本质：配菜摆盘，不是洗菜。
Phase 2 — model.py语义矛盾
主要矛盾：原始信息杂乱 vs 要提取出判断
① NS Tokenizer：把几百维散乱信息压成 8 张名片
② Sequence Encoder：翻译行为日志 + Self-Attention 捕捉关联
③ Query 三件套：用少量 token 从漫长序列蒸馏精华
本质：信息蒸馏，这才是智力活。
Phase 3 — trainer.py + utils.py训练矛盾
主要矛盾：模型当前状态 vs 理想状态，如何高效逼近
① 一个 step 8 个动作：backward "想清楚" + step "动手改"
② 双优化器：兼职员工 Adagrad + 全职高管 AdamW
③ 验证+早停：考试判好坏，连输 5 把离场
本质：反复试错，从瞎猜到变准。
train.py — 把所有矛盾串起来胶水层
train.py 不解决任何矛盾，但它知道每个矛盾由哪个文件解决，以及它们之间的信息如何传递。
schema 信息从 dataset → model；data loader 从 dataset → trainer；model 从 train.py → trainer；early_stopping 从 utils → train.py → trainer。train.py 是信息枢纽，不是矛盾解决者。
全架构检查点 — 已理解

你现在能画出 HyFormer 的完整五文件架构图，能解释每个文件的角色和它们之间的信息流：train.py 是指挥官，它调用 dataset 创建数据管道，从 dataset 提取 schema 信息构建 model，创建 EarlyStopping 和 Trainer，最后调用 trainer.train() 启动整个训练循环。五个文件各司其职，没有一个是多余的。
