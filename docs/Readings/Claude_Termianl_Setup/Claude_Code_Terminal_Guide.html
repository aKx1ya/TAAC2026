Stage One · 环 境 准 备

先有 Node.js,才有一切

DURATION ~5 min

当时遇到了什么

你直接尝试装 Claude Code,结果终端立刻甩了一行:

zsh: command not found: npm

这不是 Claude Code 的问题,是更底层的依赖没装。

为什么会这样 Claude Code 是一个 npm 全局包。npm 是 Node.js 的包管理器。 没有 Node.js,就没有 npm,就装不了任何 npm 包。 这是一条层层依赖的链条,任何一环断了,上层都用不了。

怎么解决

  1. 浏览器打开 nodejs.org
  2. 你的 Mac 是 ARM64(M 系列芯片),点 macOS Installer (.pkg)
  3. 下载完双击,一路 Continue,大约 2 分钟
  4. 验证:终端输入 node -v,看到版本号(比如 v24.15.0)就成功

安装顺序很重要 —— 先 Node.js,再 npm 包,最后 Claude Code。

关键命令
  • 验证 Node.js: node -v
  • 验证 npm: npm -v
  • 这两个都正常,才能进入 Stage 02
学到了什么
  • 看到 command not found = 没装,不是用法不对
  • 工具链是层层依赖的,从底向上看缺什么
  • 官方安装包永远比命令行 nvm 之类的省心
↓ Node.js 装好了,但还有一个更大的坑在等着
02
Stage Two · 权 限 三 连 坑

连续踩了三个坑,
每个都是权限问题

DURATION ~20 min

坑 #1 · EACCES 权限拒绝

你执行 npm install -g @anthropic-ai/claude-code,得到:

npm error code EACCES npm error syscall mkdir npm error path /usr/local/lib/node_modules/@anthropic-ai npm error errno -13 npm error Error: EACCES: permission denied
为什么会这样 /usr/local/lib 这个目录默认归 root 所有, 普通用户没有写入权限。npm 想往里面装东西,系统直接拒绝。

坑 #2 · sudo 密码看起来"卡住了"

按本能你会加 sudo:

$ sudo npm install -g @anthropic-ai/claude-code Password:

但是输密码的时候 —— 屏幕上什么都不显示。 光标在闪,你打字也没反应。看起来像卡住了。

为什么会这样 这是 macOS 的安全特性,不是 bug。 输 sudo 密码时不显示任何字符(连星号都没有),防止旁边的人通过看屏幕猜出密码长度。 你需要盲打,输完直接回车。

坑 #3 · 装到一半 symlink 又失败

就算 sudo 通过了,还会再次失败:

npm error EACCES: permission denied, symlink '../lib/node_modules/.../claude.exe' -> '/usr/local/bin/claude'
为什么会这样 包下载下来了,但要在 /usr/local/bin 创建一个快捷方式 (symlink,让你能直接用 claude 命令而不用打全路径), 这一步又卡在了权限上。

最终的一招制敌

与其每次都 sudo,不如把目录所有权一次性交给当前用户:

$ sudo chown -R $(whoami) /usr/local/bin && \ npm install -g @anthropic-ai/claude-code changed 2 packages in 771ms

看到 changed 2 packages 就是成功了。 以后再装任何 npm 全局包,都不需要 sudo 了。

chown 比 sudo 更彻底 —— 一次解决,以后都不用再 sudo。

三个错误的连环关系
  • 坑 1 引出 坑 2:用 sudo 来绕权限
  • 坑 2 误以为是 bug:其实是密码不显示而已
  • 坑 3 暴露 sudo 不彻底:还有别的目录没权限
  • 结论:用 chown 一次性修好所有相关目录
学到了什么
  • 看到 EACCES = 权限问题,不是用法错
  • sudo 密码盲打是 macOS 标准行为
  • npm 全局安装在 macOS 上经常遇到权限问题,这是一个普遍痛点
  • chown 是治本,sudo 是治标
小心
  • 不要在生产服务器上随便 chown,可能影响系统稳定
  • 但在你自己的 Mac 上,chown 自己用户名是安全的
↓ 装好了,但启动它的时候又有意外

Stage Three · 网 络 通 路

装好了,但连不上

DURATION ~3 min

当时遇到了什么

你输入 claude,看到了那个可爱的 ASCII 小猪图, 然后红字:

Unable to connect to Anthropic services Failed to connect to api.anthropic.com: ERR_BAD_REQUEST Please check your internet connection and network settings. Note: Claude Code might not be available in your country. Check supported countries at https://anthropic.com/supported-countries
为什么会这样 Claude Code 本质是一个命令行客户端,所有功能都依赖访问 api.anthropic.com。 中国大陆的网络环境无法直接访问这个域名,所以全程必须有稳定的代理。

怎么解决

  1. 开启你常用的代理工具(Clash / Shadowrocket / V2Ray 等)
  2. 有些代理工具需要额外打开 "终端代理" 或 "TUN 模式",才能让命令行流量走代理(图形界面浏览器走代理 ≠ 终端走代理)
  3. 确认代理生效后,重新输入 claude

浏览器能上 Google ≠ 终端能访问 api.anthropic.com。这是两条独立的通路。

检查代理是否生效
  • 终端输入 curl -I https://api.anthropic.com
  • 看到 HTTP/2 ... 字样 = 通了
  • 看到 Could not resolve host = 没通
学到了什么
  • Claude Code 必须能访问 api.anthropic.com
  • 终端代理 ≠ 系统代理,需要单独开
  • 这一阶段以后每次用 Claude Code 都要保持代理开启
↓ 网络通了,可以正式登录了
04
Stage Four · 启 动 与 登 录

三个选择题,都有正解

DURATION ~3 min

第一次启动会问三个问题

问题 1 · 选主题

它会展示 7 个主题选项,有 Auto / Dark / Light 等。 你的终端是深色背景,选 2. Dark mode,按 Enter。

问题 2 · 终端设置

"Use Claude Code's terminal setup?" —— 推荐设置(Option+Enter 换行等优化)。 按 Enter 选 Yes 即可。

问题 3 · 选登录方式

1. Claude account with subscription · Pro, Max, Team 2. Anthropic Console account · API usage billing 3. 3rd-party platform · Bedrock / Foundry / Vertex
怎么选 选 1 —— 你已经有 Claude Max 订阅,Claude Code 的使用额度已经包含在月费里,不用再付钱。
选 2 是按 API 用量额外付费(适合开发者大量调用)。
选 3 是企业用户走云厂商(用不到)。

浏览器授权

选完后会自动打开浏览器:

  1. 系统弹窗 "Terminal would like to access files on a network volume" → 点 Allow
  2. Claude 网页 "Claude Code would like to connect to your Claude chat account" → 点 Authorize
  3. 回到终端,看到 Login successful. Press Enter to continue 即成功
登录方式对比
  • Subscription(你用的):走 Claude 订阅,额度包含在月费内,适合个人
  • API key:按 token 用量付费,无月费,适合开发者大量自动化
  • 对你而言:Subscription 完全够用,以后真正大规模用了再考虑 API
学到了什么
  • 登录是一次性的,登录信息会保存,以后启动不需要再登
  • 授权页面是 OAuth 标准流程,跟微信扫码登录一个原理
  • 这一步走通,代表你的 Claude 账号和终端正式绑定了
↓ 快了,还差最后一道安全确认

Stage Five · 工 作 区 信 任

"你信任这个文件夹吗?"

DURATION ~30s

它会问什么

Accessing workspace: /Users/xuzijian/Desktop/bag_store Quick safety check: Is this a project you created or one you trust? › 1. Yes, I trust this folder 2. No, exit
为什么会问这个 Claude Code 会读、写、执行你这个目录里的文件。 如果你不小心进了一个别人的恶意项目,Claude Code 可能在你不知情的情况下执行恶意代码。 所以它会问一次:这个文件夹真的是你的吗?

怎么做

按 Enter 选 "Yes, I trust this folder"。 这个选择会被记住,下次进同一个目录不会再问。

关于桌面客户端的 WorkspaceTrustError

你之前用桌面客户端时反复看到:

WorkspaceTrustError: Workspace requires trust approval before starting a session.

这是已知 bug(GitHub 上多个 issue 在追踪), 桌面客户端的"信任"按钮在某些场景下没有正确保存状态。 Anthropic 还在修。

终端版可以完美绕过这个 bug —— 这就是今天我们切到终端的根本原因。

客户端 vs 终端 今天的对比
  • 客户端:WorkspaceTrustError 反复出现,无法绕过
  • 终端:同样的信任机制,但能正常保存,一次确认终身有效
  • 客户端的 bug 修好之前,终端是更可靠的选择
学到了什么
  • "工作区信任"是安全机制,不是麻烦
  • 客户端封装的越多,出问题时越难排查
  • 终端版更"透明",每个错误你都能看到原因
↓ 终于到了,你的第一次对话

Reflections · 关 键 启 示

不是命令,而是这些

REFLECTION 01

错误信息是朋友,不是敌人

每次报错都是系统在告诉你"这一步缺什么"。 EACCES = 权限,command not found = 没装, Unable to connect = 网络。读懂关键词,问题就解决了一半。 以后看到红字不要慌,先把关键词挑出来。

REFLECTION 02

工具链是层层依赖的

Claude Code 依赖 npm,npm 依赖 Node.js,Node.js 需要安装权限, 全部需要联网。任何一层断了,上层都用不了。 以后排查问题从底向上:先确认网络,再确认基础工具,最后看应用层。

REFLECTION 03

终端比客户端更可靠

客户端封装得多,出问题时排查难。终端版每个错误都是透明的, 你能直接看到原因。今天的 WorkspaceTrustError 就是最好的例子 —— 客户端绕不过,终端一秒解决。新手反而更应该用终端。

REFLECTION 04

走过一次就会了

你今天踩的所有坑,下次都不会再踩 —— 因为 Node.js 装好了、 权限修好了、登录信息保存了、你也知道客户端的 bug 了。 这就是 Phase 0(启动阶段)的全部价值: 一次性把基础设施搞定,后面专注思考创造。

你不是在学一个工具 ——
你是在学一种新的工作方式。
