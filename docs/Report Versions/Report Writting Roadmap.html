3.C English Template · 英文写作模板

We formulate click-through rate (CTR) prediction as a binary classification task. Given a user u, a candidate item i, and the user's historical behavior sequences across D = 4 heterogeneous domains S = {Sa, Sb, Sc, Sd}, the model outputs a probability ŷ = f(u, i, S) ∈ [0, 1].

The training objective is the standard binary cross-entropy loss: L = −[y log ŷ + (1−y) log(1−ŷ)], where y ∈ {0,1} denotes whether the impression resulted in a click.

We use the TAAC 2026 Academic Track dataset, which consists of ~1M impression records derived from real-world Tencent advertising logs. Each record corresponds to a single (user, item, timestamp) impression, augmented with the user's preceding behavior across multiple domains.

The dataset is fully anonymized: all sparse features are mapped to integer IDs, all dense features are presented as fixed-length float vectors, and no raw content (text, images, URLs) or personally identifiable information is preserved. As a consequence, pre-trained language or vision models cannot be leveraged for feature extraction — methodological contributions must come from architecture design rather than external knowledge transfer.

Each record is stored in a flat schema of 120 columns, partitioned into six categories (Table X): five ID/label columns, 46 user integer features (35 scalar + 11 multi-value), 10 user dense features, 14 item integer features, zero item dense features, and 45 domain sequence features distributed across four behavioral domains.

A distinctive feature of the schema is the aligned (key, value) structure: eight of the ten user-dense columns are positionally aligned with their integer counterparts, encoding per-element behavioral statistics (e.g., dwell time, interaction score) for the corresponding entity IDs.

The 45 sequence columns are partitioned into four heterogeneous behavioral domains, denoted A through D, with column counts 9 / 14 / 12 / 10 respectively. While the precise semantics of each domain are not disclosed by the dataset provider, the domains differ in average sequence length (256 for A/B, 512 for C/D) and likely correspond to distinct interaction modalities.

Within each domain, multiple columns are positionally aligned: the i-th element across all columns of domain d describes the i-th historical action (e.g., its item ID, category, timestamp). Continuous timestamps are discretized into 65 logarithmically-spaced buckets ranging from seconds to years, so that the model receives a learnable temporal embedding rather than raw Unix time.

4.1.C English Template

We build directly on the official baseline released by the competition organizers, denoted PCVRHyFormer. As clarified at the outset, this section describes the baseline architecture; our own modifications are deferred to Section 4.2.

PCVRHyFormer is a hybrid Transformer in the spirit of HyFormer [Liu et al., 2026]: it interleaves sequence modeling with feature interaction within a single stack of N identical blocks. The model takes the 120-column input described in Section 3 and produces a click probability via N stacked MultiSeqHyFormerBlocks followed by a final classifier head.

The block operates over three semantically distinct token types, jointly forming the unified token stream:

① Non-Sequential (NS) Tokens. The user and item static features (Section 3.3) are aggregated into a fixed set of NS tokens via a tokenizer module. We follow the default RankMixer configuration with 5 user + 2 item NS tokens.

② Sequence Tokens. The four behavioral domains (A–D) are encoded independently. Each domain's per-position features are projected into dmodel-dimensional embeddings, augmented with rotary position encoding (RoPE) and time-bucket embeddings.

③ Query (Q) Tokens. A small set of num_queries = 2 learnable query tokens act as a learnable read-out: they cross-attend over the sequence tokens of each domain to extract behaviorally relevant signals before being mixed with the NS tokens.

Each MultiSeqHyFormerBlock performs four sub-operations in succession:

(i) Sequence Evolution. Within each domain, sequence tokens undergo causal self-attention with rotary position encoding, refining their per-position representations.

(ii) Query Decoding. The Q tokens cross-attend over each domain's evolved sequence tokens, gathering one read-out vector per (query, domain) pair.

(iii) Token Mixing. NS tokens, the gathered Q outputs, and the sequence tokens are concatenated into a unified stream of length T = num_queries × num_sequences + num_ns, then passed through a Transformer-style attention block. This is where deep static–sequential fusion takes place.

(iv) Query Boosting. The refined Q-token slots are fed back as inputs to the next block's query decoding step, allowing the queries to progressively focus on more discriminative behavioral patterns.

After N blocks, the final Q tokens are pooled and passed through a feed-forward classifier (clsfier) producing the click probability ŷ.

2.C English Template

Feature interaction models aim to capture cross-feature dependencies among static categorical and dense attributes. Early work such as Factorization Machines [Rendle, 2010] represents pairwise interactions through low-rank factorization. DeepFM [Guo et al., 2017] and DCN [Wang et al., 2017] extend this idea by combining explicit cross-products with deep MLPs.

More recent designs — AutoInt [Song et al., 2019], FinalMLP [Mao et al., 2023], Wukong [Zhang et al., 2024] — focus on scalable high-order interactions and improved expressivity. None of these architectures, however, model temporal user behavior; they treat each impression as an i.i.d. tabular row.

Sequential recommendation models exploit the temporal structure of user behavior. GRU4Rec [Hidasi et al., 2015] initiated the line with recurrent encoders, while DIN [Zhou et al., 2018] and DIEN [Zhou et al., 2019] introduced target-aware attention to weight historical actions by relevance to the candidate item.

Transformer-based encoders — SASRec [Kang & McAuley, 2018], BERT4Rec [Sun et al., 2019], BST [Chen et al., 2019] — pushed the field toward longer contexts and richer attention patterns. Recent work such as TWIN [Chang et al., 2023] and HSTU [Zhai et al., 2024] explores extreme sequence lengths under industrial latency budgets. These models, conversely, rely primarily on sequential signals and integrate static features only superficially.

Bridging the two paradigms has emerged as an active research direction. InterFormer [Author, 2024] proposes [一句话总结其方法]; OneTrans [Author, 2025] argues for [一句话总结其方法]; HyFormer [Liu et al., 2026] introduces a hybrid block that interleaves sequence evolution with cross-domain query decoding, and forms the architectural basis of the official baseline of this competition.

Our work builds directly on the HyFormer-based baseline. [Position your contribution here once teammate confirms direction — e.g., "We focus on improving cross-domain temporal alignment / NS tokenization / time-bucket design / ..."]

1.C English Template — Full Intro Skeleton

¶1 · Hook

Modern industrial recommender systems have evolved along two largely independent trajectories. Feature interaction models — from FM to DeepFM, DCN, and Wukong — capture rich cross-feature dependencies over static user and item attributes. Sequential recommendation models — from GRU4Rec to SASRec and HSTU — exploit the temporal structure of user behavior. Despite a decade of parallel progress, unifying these two paradigms within a single architecture remains an open problem.

¶2 · Pain Points

This separation imposes four concrete costs on production systems. (i) Shallow cross-paradigm interaction: most existing pipelines combine the two branches only at the final classifier, discarding rich cross-modal signals. (ii) Inconsistent optimization objectives: sequential branches often rely on contrastive losses while interaction branches optimize binary cross-entropy, complicating joint training. (iii) Limited scalability: unlike large language models, recommender architectures plateau quickly when scaled up — the field lacks a clear scaling law. (iv) Engineering complexity: maintaining two heterogeneous code paths inflates deployment, monitoring, and iteration costs.

¶3 · Setting

The TAAC 2026 Academic Track provides a controlled testbed for tackling this gap: ~1M impressions sampled from real-world Tencent advertising logs, structured into 120 columns spanning static user/item features and four heterogeneous behavioral domains. The competition releases an official baseline, PCVRHyFormer — a HyFormer-based hybrid Transformer — alongside a strict latency budget that rules out naive scaling.

¶4 · Contributions

We build on PCVRHyFormer and contribute the following:

• [Contribution 1 — e.g., "We re-design the NS-token grouping based on ..., yielding +X.XX AUC."]

• [Contribution 2 — e.g., "We propose a refined time-bucket scheme that ..."]

§ 05 · Writing Craft

写作 tips · 让 reviewer 一眼看出你是认真的

NeurIPS 风格论文不是堆术语比赛。下面这 8 条来自一线审稿人的偏好 — 遵守它们,你的文章读起来就像"自己人写的",不遵守就会显得"AI 生成感"。

01 一句话 = 一个观点

NeurIPS 写作偏好短句。不要写长达 3 行的中文式复合句。每句话只承载一个核心观点,有从属信息就开新句。

反例:"Although baselines suffer from problems, our method, which is based on a novel design, addresses them by improving X, leading to better Y."

02 主动语态 + I/We

NeurIPS 现在鼓励用 "We propose..." 而不是被动的 "It is proposed that...". 后者显得生硬、AI 味重。

03 数字要精确

不要写 "我们的模型显著好于 baseline"。要写 "+0.0042 AUC over the baseline (0.7823 → 0.7865, p < 0.05)"。具体数字 = 可信度。

04 图表自洽

每张图 / 表的 caption 必须能独立读懂。不要写 "Figure 2: Our method." 要写 "Figure 2: Architecture of PCVRHyFormer. Three token types interact via N stacked blocks; final Q tokens are pooled for classification."

05 诚实标注 baseline

每次提到 baseline,都要让读者清楚这不是你做的。开头一句 "We build on the official baseline (PCVRHyFormer) ..." 后,所有"我们改了"的部分必须有清晰的 "Our X" / "we modify Y" 标记。

06 用 LaTeX 排公式

所有数学符号(x, ŷ, L) 用 $...$ 写,变量用 \mathit{}。不要在 Word 里直接打 "y_hat" 这种 ASCII。

07 引用要密但不堆砌

9 页 NeurIPS 通常引用 15-25 篇。Related Work 是引用密度最高的(每个声明都要有 cite),Method 章节引用最少(那是你自己的工作)。

08 一定要写延迟分析

这是 TAAC 2026 的特殊要求。Section 5 必须有一段说明你的方法 "satisfies the official latency budget",即使你不写具体毫秒数。
