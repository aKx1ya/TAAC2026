第一站 · Station I

什么是 baseline?

Establishing the starting line

这是整个项目里最容易被默认"你已经懂了"的术语,也是我最先卡住的地方。

在 AI 比赛和学术研究里,baseline = 一个已经能跑通、有合理效果、被当成"起跑线"的现成方案。它同时扮演两个角色:

角色 含义
起点(脚手架) 主办方先做好一个"过得去"的方案,代码、模型、训练流程全部打包好。我不需要从一张白纸开始。
对照组(参照系) 我所有的改动,都要拿原始版本来对比。baseline 的 AUC 是 0.78,我改完是 0.81,这个 +0.03 才是我的贡献。
比喻 · Analogy

🍳 改良红烧肉

报名一个烹饪比赛。主办方说"做一道改良版红烧肉",并且直接给我一份完整能用的红烧肉菜谱。我的任务不是从买肉开始,而是在这份菜谱上做改良——换种糖、加点八角、调整火候——然后比一比改完的版本是不是更好吃。

guide 里那"7 个文件"(run.sh / train.py / model.py...)就是腾讯发来的这份完整菜谱。

baseline 是别人的工作。我只能拿"在 baseline 上做的改动"作为自己的 contribution。把整个 baseline 写成"Our Method" = 学术不端。

第二站 · Station II

我们的角色定位

Improvers, not inventors

抓到了一句最核心的认知:

"本质上,我们是在原有的基础上做 improvement,而不是从 0 开始打满全场。"

这不是偷懒,而是学术研究和工业实践的标准做法。几乎所有论文都遵循这个套路:

  • 先承认"前人做了 A"
  • 再说"A 有个问题 / 还可以更好"
  • 最后讲"我们提出 B,在 A 上做了 X、Y、Z 三个改动,效果提升了多少"

为什么必须基于 baseline,而不是从零开始

原因说明
时间课程只剩 5 天。从零设计一个工业级推荐模型 → 几个月。课程项目完成不了这个体量。
公平比较每队各自从 0 开始 → 数据预处理、训练流程、评测方式全不一样,根本比不出谁的"模型创新"更好。统一 baseline = 控制变量,只比较"我的改动"。这就是科学方法。
真问题工业界的工程师 99% 的时间不是在"发明新模型",而是在"接手一个已有系统、找到瓶颈、做改进、证明改进有效"。比赛模拟的就是这种场景。

什么样的"改进"才有说服力

每一个改动都要满足两点:

Motivation(动机) · 你为什么改这个地方?是发现了 baseline 的什么缺陷?

Evidence(证据) · 改完之后真的更好了吗?用对比实验(消融实验)证明。

反例 vs 正例

怎么写改动才不被审稿人质疑

❌ 反例:"我们把 num_heads 从 4 改成 8,AUC 提升了 0.001。"
→ 没动机、提升微弱、像瞎试。

✅ 正例:"我们注意到 baseline 在长序列(domain c, d)上效果差,猜测时间桶粒度太粗。我们把 num_time_buckets 从 65 增加到 128,并在 ablation 中验证了这一改动在长序列上贡献了 +0.008 AUC,而在短序列上几乎没变化。"
→ 有观察、有假设、有验证、效果可解释。

核心心智模型:我的角色是模型改良者,不是模型发明家。我的价值在于:找到 baseline 的弱点 + 提出针对性的改动 + 用实验证明改动有效。这三件事做得清楚,就是一篇好 report。

第三站 · Station III

30秒电梯演讲拆解

Anatomy of the elevator pitch

guide 开篇那段"如果有人突然问'你们这个项目在做什么?'就照这段讲"的演讲,其实是把整个项目压缩进了三句话。每句话回答一个问题:

第一句 · Why
两类 AI 模型一直没法很好地融合(行业难题)
第二句 · What
在 100 万脱敏广告日志上做 CTR 预测(具体任务)
第三句 · How
在腾讯 baseline 上改进 + 写 9 页 report(我的角色)

三句话的功能

句子它在回答的问题对应的 Level
第一句 · Why这件事有意义吗?Level 1 行业难题
第二句 · What具体在做什么?可执行吗?Level 2/3 比赛任务
第三句 · How我的贡献边界在哪?Level 4 课程交付

电梯演讲的设计原理:从抽象到具体,层层收紧。第一句让对方觉得"哦这事儿值得做",第二句让对方明白"具体在做什么",第三句让对方知道"你的位置在哪里"。任何人(队友/教授/面试官)看完都能立刻 get 我的项目。

自检练习:不看原文,试着用一句话讲——"我在参加一个广告推荐的比赛,工业界一直有个难题是两种 AI 模型融合不好。我们拿了腾讯给的 baseline 代码,在它基础上做改进,最后要交一篇 9 页报告。"

第四站 · Station IV

两类模型的本质区别

Feature Interaction vs. Sequential — same data, different lenses

名词对照

中文英文关键词
特征交互模型Feature Interaction Models静态属性、标签组合
序列模型Sequential Recommendation Models行为时间线、演化趋势

本质区别

我之前的理解:特征交互模型针对"有标签的用户",序列模型针对"可能没有标签、只有行为顺序的用户"。两者关注的是不同的数据。

更精确的理解:两个模型面对的是同一个用户的同一份数据,只是各自关注不同维度。

序列里的每一个"行为"本身也带很多属性标签(商品ID、类目、品牌、价格、时间戳)。所以序列模型也"看得到"标签——它只是更关注这些标签随时间的演化。

比喻 · Analogy

🩺 两位医生看同一份病历

特征交互模型 = 内科医生:看你的化验单(年龄/血型/各项指标),关注当下身体状态的各个数字之间的组合。

序列模型 = 病史专家:翻你过去 3 年的就诊记录时间线(去年咳嗽、半年前过敏、上周失眠),关注症状随时间的演变。

同一份病历,两位医生看到的是同一个人,但提取出的信息维度不同。

核心矛盾:为什么"两边都有信息"≠"已经融合了"?

关键在于融合发生在"模型内部"还是"模型外部":

❌ 浅融合(shallow fusion) · 现有做法
   模型A处理静态  → 输出向量 A
   模型B处理序列  → 输出向量 B
   最后 [A; B] 拼一起 ← 信息浪费严重

✅ 深度融合(deep fusion) · 比赛要的
   一个统一模型,在"思考"过程中
   静态信息和序列信息互相影响、互相印证

用警局破案的比喻来讲:现状是侦探 A 写一份报告 + 侦探 B 写一份报告 + 管理层硬拼接两份结论。比赛要的是训练一位新型侦探,他自己一个人就能同时看档案 + 看录像,而且能在脑子里把两类信息相互印证。

PCVRHyFormer 名字里的 "Hy" = Hybrid(混合)。它的设计目标就是把两类信息融合在同一个大脑里——这是整个项目要解决的核心命题。

第五站 · Station V

数据的真实面貌

100万 / 120列 / 4域 / 脱敏 — what each really means

① 脱敏(Anonymization)

字面意思:把"敏感信息"脱掉——去掉所有能识别到具体个人的内容。

原始数据(违法,不能给):
用户:张伟,身份证310...,手机139...,昨天14:23点了《王者荣耀》广告

脱敏后(发出来的):
用户:user_id=87234691,特征列1=15,特征列2=3,昨天点了 item_id=556712

所有原本有意义的信息(姓名、地点、广告内容、用户兴趣类别)都变成了纯数字 ID 或抽象数值。

这对建模意味着什么?

  • 不能用预训练 LLM/CV 模型做特征工程(因为没有自然语言或图片可以理解)
  • 所有 ID 必须靠 embedding 学习(让模型自己摸索每个 ID 的"含义")
  • 模型学的是统计模式,不是语义理解

— 这有点像"探索黑暗地图":数据是真实的,但每个标签的含义需要模型自己从模式中"猜"出来。

② 100 万样本的真实含义

我之前的理解:100 万样本 = 100 万个人。

正确理解:100 万样本 = 100 万次"曝光记录"(曝光 = 一次"用户看到广告"的事件)。同一个人可以出现多次。

样本编号  用户ID    时间       广告      点了吗?
─────────────────────────────────────────────
1        user_A   08:00:23  广告 X    否(0)
2        user_A   08:05:41  广告 Y    是(1)   ← 同一个人
3        user_B   08:10:23  广告 X    是(1)
4        user_A   14:30:12  广告 Z    否(0)   ← 同一个人,时隔6小时
...

关键认知:

  • 每条样本都有精确时间戳(到秒甚至毫秒),所以同一个用户基本不会"同一时间出现两次"
  • 不同用户可以同一时刻出现(整个广告系统是全网同时运行的)
  • 时间间隔完全不规则,取决于用户使用习惯(重度用户密集出现,轻度用户稀疏出现)
  • 背后真实的人数少于 100 万,可能只有几十万,但他们累积起来产生了 100 万次曝光

③ 120 列的内部结构

每条样本(每一行)有 120 个特征列。这 120 列不是同一类性质:

120 列总览(单个样本视角)
──────────────────────────────────────────────
🔖 ID 和 label              5 列    "这条记录的元数据 + 答案"
👤 用户静态特征             56 列   "这个用户是谁"  (46 离散 + 10 稠密)
📦 商品静态特征             14 列   "这个广告是什么"
📜 用户行为序列             45 列   "这个用户最近在干什么"
                                   └── 分散在 4 个域(a/b/c/d)
                                   └── 每列装的是一串值,不是一个值
──────────────────────────────────────────────

④ 序列列 vs 普通列

普通列(装一个值):

user_age = 30
user_gender = "male"

序列列(装一串值,带顺序):

seq_a_item_id = [556712, 887341, 661203, 998765, 113344, ...]
                  ↑       ↑       ↑       ↑       ↑
                  最早    →    →    →    →    最近的行为

⑤ 4 个行为域(domains a / b / c / d)

"行为域"指用户行为发生的不同场景。同一个用户在不同场景下行为模式不同,把他们分开处理,模型才能在每个语境里看清规律。

比喻 · Analogy

🛒 超市的会员系统

同一位顾客在超市里穿梭于不同区域,每个区域都有他独立的行为时间线:

区域(域)这位顾客的行为
🥬 生鲜区周一西兰花 → 周二三文鱼 → 周三牛排
📚 书籍区翻3本小说 → 买1本经济学
👕 服装区试穿2件外套 → 没买
☕ 咖啡区每天早上必买拿铁

如果把所有区域的行为搅成一个长流水账(西兰花 → 小说 → 拿铁 → 三文鱼...),模型会一脸懵。分域处理 → 每个域自成一个语境 → 模型在每个语境里看清规律 → 最后融合。

腾讯的 4 个域(a/b/c/d)具体是什么没有公开(因为脱敏),但可以推测代表 4 类不同性质的业务场景或行为类型(信息流 / 搜索 / 视频 / 应用 等)。具体是什么不重要,知道"4 类不同的行为序列,模型分开处理"就够了。

⑥ 串起所有概念的整体图景

数据是真实但脱敏的
        ↓
100 万条曝光记录(不是 100 万个人)
        ↓
每条记录有 120 个特征列
        ├── 静态特征(用户/商品标签)        ← 特征交互模型擅长
        └── 4 个域的行为序列                ← 序列模型擅长
                ↓
        两类信息都在数据里,但传统模型只能"各管一摊"
                ↓
        比赛要的是:用一个统一模型,内部深度融合两类信息
                ↓
        预测:这次曝光会不会被点击(0/1)
第六站 · Station VI

自检三问

Three checkpoint questions

如果能答出下面三题,说明前五站的内容都消化了。先尝试自己回答,再展开看答案。

Q1 同一个用户在 100 万样本里出现 5 次,这 5 次的"用户静态特征(46 列)"是一样的吗?

基本上一样(因为他还是同一个人,年龄/性别这些短期不变)。

但他的 "行为序列(45 列)" 会不一样,因为每一次曝光发生时,他过去的行为时间线截止点都不同。

想象你的朋友圈:你"今天发的内容"是固定的,但"你过去看过别人发的内容"取决于"你现在打开 APP 的那一刻"——这个截止点每次都不同。

Q2 一个序列列(比如 seq_a_item_id)和一个普通列(比如 user_age)最大的区别是什么?

普通列装一个值,序列列装一串值(list)。

而且序列列还隐含顺序信息——位置 1 的元素比位置 5 的元素发生得早。这种顺序本身就是信号。

Q3 如果腾讯不脱敏,直接给"用户A在3月15日看了《王者荣耀》广告",这种数据反而更难处理吗?

难处理多了:

  • 涉及隐私法律风险(GDPR / 个保法)
  • 需要 NLP 特征提取(分词、语义、情感)
  • 不同广告之间没法直接比较(《王者荣耀》和《和平精英》的"语义距离"怎么算?)
  • 引入了无关的语言学复杂度

脱敏成纯 ID 反而让模型设计专注在"模式发现"上,排除了所有语义噪音。所以"脱敏"不是数据的缺陷,是对建模任务的简化。
